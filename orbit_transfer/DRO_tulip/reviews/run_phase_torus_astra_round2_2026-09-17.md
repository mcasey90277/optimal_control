## B. Findings in the current rewrite

- **[CORRECTNESS]** `run_costate_library.m:239–243`; `build_arrival_sheet.m:53,89`; `run_phase_torus.m:560–562`; `fill_holes_direct.m:97–100` — **Campaign setup loses the requested departure phase and anchor context.** Sheet construction receives neither `sD(1)` nor the campaign anchor and its arrival phase. It therefore calls `arclength_arrival('setup', ...)` using departure phase zero and the shipped anchor at `0.0754`. A nonzero departure origin builds the wrong sheet and subsequently fails the grid assertion at `run_costate_library.m:270–272`; a different engine can fail the shipped anchor’s operating-point check after spending hours producing valid campaign arcs. Separately, filler and discovery pass the first campaign anchor but omit its `sA0`, causing that anchor to be re-solved at `0.0754` regardless of its actual phase. **Fix:** thread a complete campaign setup context into the sheet builder. For filler and discovery, use `physicsOnly=true`: they need endpoint/physics closures, not an anchor polish. Add acceptance cases with nonzero `sD(1)`, a non-`0.0754` anchor and nondefault propulsion.

- **[CORRECTNESS]** `run_phase_torus.m:130–145,169–172` — **Resume compatibility stops at the physical problem and grid.** Changing `.arc.span`, `.arc.nStep` or an anchor file’s contents leaves existing arcs reusable solely by filename. Supplying a different initial anchor table is silently ignored after loading `st.anchors`. The exact phase vectors *are* protected; that part is not missing. **Fix:** persist immutable initial-root IDs/content hashes, construction-policy versions and per-arc input signatures. Reject incompatible changes or explicitly schedule replacement/extension of affected products. Distinguish mutable search budgets from immutable campaign identity instead of silently ignoring changes.

- **[ROBUSTNESS]** `run_phase_torus.m:169–182,421–444` — **Recorded arc PIDs provide no resume ownership.** A resumed call launches every missing MAT again without inspecting `st.jobs`; it appends new PIDs to the old list. That list is cleared only after all jobs succeed. At a later deadline, `kill` is sent to every stored PID, including exited jobs whose PID might have been reused. Only the listed PID is targeted—not an established process group—and termination is not confirmed. A `.fail` exits without cancelling siblings. **Fix:** hold an outer campaign-controller lock, persist each launch immediately with attempt ID and verifiable process identity, adopt live owned jobs, and cancel only owned process groups with bounded TERM/KILL-and-wait handling. Bound simultaneous arc launches as well; currently every missing arc starts a MATLAB session and pool at once.

- **[ROBUSTNESS]** `run_phase_torus.m:430–436,459–473,482–485` — **The arc verdict protocol is neither attempt-specific nor startup-complete.** Old `.fail` files make retries fail immediately; old `.done` files can satisfy a new wait. Conversely, startup/path/pool errors occur before the generated `try`, and MATLAB launch failure produces no verdict. `nohup ... & echo $!` returning a PID proves only that the shell started a background command, not that MATLAB initialized successfully. Existing MAT files also bypass verdict checking altogether. **Fix:** give each attempt unique temporary/output/verdict names and publish an atomic terminal record naming its input signature and MAT product. Have a shell wrapper report startup/exit failures and have the controller check process liveness. Preserve and explicitly resume or retire partial checkpoints rather than simply launching over them.

- **[CORRECTNESS]** `run_phase_torus.m:494–507,660–665` — **Supervisor adoption still accepts the wrong generation—and can wait 48 hours for a verdict already written.** `dir(...).datenum` is a filesystem modification time expressed as a MATLAB serial date number, not an attempt identifier. An old supervisor that finishes after `before` can satisfy the wait. In the opposite race, an adopted supervisor has already written its terminal verdict but has not exited: `before` captures that verdict’s timestamp, so the driver waits for a rewrite that will never occur. A newly visible empty/nonterminal file is read immediately rather than awaited. The `pgrep -f` pattern also treats `V` as a regular expression; shell quoting does not escape regex metacharacters, and on shells retaining a `-c` ancestor that ancestor can match the pattern itself. **Fix:** identify supervisors through a persisted lease/attempt record, accept only that attempt’s atomic terminal result, and confirm exit before modifying its inputs. Adoption must precede mutable round preparation, not merely the launch call.

- **[ROBUSTNESS]** `run_phase_torus.m:459–482,714–726`; `run_costate_library.m:665,721` — **Valid paths and advertised execution options still fail outside the happy-path installation.** `mlq` correctly doubles MATLAB quotes and `shq` correctly quotes POSIX arguments, but line 482 constructs `run('...')` using the raw filename. A campaign path containing an apostrophe therefore becomes invalid MATLAB source despite correct shell quoting. MATLAB `run` executes a script from its containing folder, so a relative `.startup` is resolved relative to `jobs/`, not the caller. Global `strrep(jobFile,'.m','.out')` can also alter directory components. Finally, `.startup` and `.matlab` are used only by arc launching; generated rib/finalizer jobs retain a hard-coded startup directory, and the driver does not forward the chosen MATLAB binary to their launcher. **Fix:** construct `sprintf('run(%s)', mlq(jobFile))`, canonicalize configured paths at input time, form sibling filenames with `fileparts`, and propagate execution settings through the entire job stack.

- **[CORRECTNESS]** `run_phase_torus.m:193–209,643–651`; `run_costate_library.m:321` — **The stale-rib gate does not test the condition it claims to test.** A rib’s first point is a departure target, not its source spine: `rib_targets.m:47` explicitly removes the spine from the target list. Its flight time can legitimately differ substantially from the spine, especially on arbitrary phase lists. Conversely, another family’s first point within 0.5 day passes. This is unrelated to the `1e-6` day / scaled `1e-9` root comparison above it. Validation also runs only on `changed` columns, not every existing destination rib. **Fix:** store and validate explicit source-root identity, source phases, grid/problem identity and checkpoint generation. Compare that metadata for every reused rib; quarantine incompatible publications and their checkpoints under ownership protection. Do not infer source identity from the first walked point.

- **[CORRECTNESS]** `run_phase_torus.m:524–532,594–604,618–622,635–639`; `run_costate_library.m:238–244` — **Promotion remains a nontransactional sequence, and cached sheets conceal recovery work.** A crash after registry publication but before promotion leaves a registered, unanchored root; the filler path will not reconsider it because promotion requires `added=true`. A crash after writing the anchor but before saving state leaves an orphan file that a subsequent promotion refuses to overwrite. After a saved promotion, resume can walk its new arcs but reuse the existing round sheet, because the sheet builder is invoked only when its filename is absent. The new arcs and registry roots then need not enter that round at all. **Fix:** journal root acceptance and promotion state under immutable root IDs, reconcile unfinished transactions before stages run, and key sheet reuse to its actual arc/root input manifest. Rebuild in a new generation when those inputs change.

- **[CORRECTNESS]** `run_phase_torus.m:598–616` — **Promotion can anchor an already anchored root, and the name allocator is not generally unique.** Discovery does not require that `best` be newly registered or unanchored. Since it uses pre-fill `S` and a family map derived only from `S.arcs`, it can rediscover a root just promoted by the filler and create a second anchor for it. Separately, `nnz(startsWith(...,base))` counts matching prefixes; it does not find the maximum suffix or an unused name. An allowed initial anchor named `d03_2` makes the next generated name `d03_2` when it is the only matching prefix, and the file-existence assertion need not catch the duplicate table name. **Fix:** enforce one anchor per immutable root ID, include pending anchors in promotion decisions, and reserve names using a monotonic persisted counter or UUID while checking both registry names and files.

- **[CORRECTNESS]** `run_phase_torus.m:215–233`; `fill_holes_direct.m:109–126,148,155,230–238` — **A resumed filler’s saved roots can disappear from the catalog and never be registered.** `fh.nCert` counts certifications performed by the current call, not certified points already present in `fh.file`. On resume, the initial `runRound` packages without the current round’s holes file; the filler then loads that file, skips its already successful cells and can return `nCert=0`. The driver consequently skips both registration and repackaging. It can publish a catalog missing roots that are safely present on disk. **Fix:** offer every valid persisted current-round direct-rib file to packaging, reconcile its spine roots regardless of this invocation’s counter, and decide whether to repackage from product/root-generation changes—not `fh.nCert > 0`.

- **[CORRECTNESS]** `run_phase_torus.m:578,635`; `family_map.m:240–266` — **Root deduplication and family exclusion use flight-time proximity as identity.** Two distinct costate roots at the same phase within `1e-3` day are collapsed in both the probe seed pool and registry. Family attachment then treats a time within `0.02` day of an interpolated arc as belonging to that family, without comparing shooting data. Near a family crossing—or under the newly configurable physical problems—this can suppress precisely the new branch that needs continuation. **Fix:** use phase plus normalized shooting/trajectory identity for deduplication. For family attachment, compare against an exact-phase continuation root or verified trajectory; treat ambiguous time matches as unresolved, not evidence forbidding promotion. This concerns family identity, not a demand for a global minimum certificate.

- **[CORRECTNESS]** `run_phase_torus.m:225–251` — **The fixed-point count omits work that can enable another round.** Only filler roots on the spine contribute to `nRegistered`; newly certified off-spine cells do not. Such a cell can become a new seed for a hole that failed earlier in the filler’s ordering, so terminating immediately can stop before another productive pass. Filler promotions also never increment `newAnchors`: the 09-16 log’s `NEW ANCHOR d03_1` followed by `0 new anchor(s)` is explained exactly by this code. In that particular round, the one registered root still correctly keeps the loop running. **Fix:** count newly admitted distinct roots across the catalog, count promotions from both paths, and retain pending continuation/target-seed work explicitly. Do not substitute raw `fh.nCert`, which could count rediscoveries. Roots less than `1e-3` day apart are currently deduplicated, so that jitter alone does **not** keep this loop running forever; larger apparent differences can consume the round budget, but `maxRounds` still bounds one invocation.

- **[CORRECTNESS]** `run_phase_torus.m:217,232`; `run_costate_library.m:518–531,668–671` — **“Packaged” is being used as an audit/sweep success gate that it is not.** The callee appends chain blockers and then sets `out.state='packaged'` when this invocation wrote a catalog receipt. It does not require the audit/sweep blockers to be absent. The generated finalizer uses the same state-only success test, allowing a supervisor’s successful exit to conceal those blockers. **Fix:** return explicit package, audit and sweep outcomes bound to the catalog generation, and enforce all required outcomes. Separate permissible coverage-hole notices from fatal verification blockers. Use the existing no-rib stage switch for repackaging, retaining its completion barrier.

- **[CORRECTNESS]** `run_phase_torus.m:236–255,264–281` — **Last-allowed-round discovery is still omitted from `final`.** Discovery writes registry roots and anchors after the last catalog was packaged. Updating `common.seedFiles` does not consume them; no subsequent sheet/package/audit/sweep pass occurs before copying the last round’s products. The status is now correctly called `budget` when work was registered, but the library of record still omits committed discoveries. **Fix:** before publication, build a final generation from all committed certified roots, without requiring further continuation. Force sheet freshness rather than relying on its existing filename, package all available roots, and audit/sweep that generation. Report pending arcs separately.

- **[ROBUSTNESS]** `run_phase_torus.m:148–151,257,264–288` — **Terminal state can permanently certify an incomplete final publication.** State becomes `done` or `budget` before final construction. The driver then removes the old `final` directory before checking/copying all required products. A crash or failed copy leaves no complete final library, yet resume returns “nothing to do” without checking it. Fresh-directory construction avoids stale optional files on a successful run, but not this failure mode. **Fix:** persist a recoverable publication phase; build and validate a versioned final directory, including catalog/receipt/audit/sweep generation consistency; atomically switch the publication reference; only then commit terminal status. Resume must finish or repair an interrupted publication.

- **[CORRECTNESS]** `run_phase_torus.m:148–151,252–255` — **The prescribed budget-resume operation cannot work.** The recorded reason says “raise `.maxRounds` and rerun,” but every persisted `budget` campaign returns before examining the new bound. **Fix:** allow a budget-limited campaign to resume when the new bound exceeds `roundsDone`, using its retained pending work. Keep `done` closed unless explicitly reopened; do not advise deleting the state file as the normal extension mechanism.

- **[CORRECTNESS]** `run_costate_library.m:274–308`; `run_phase_torus.m:303–305,354–355` — **The advertised one-departure-phase case is blocked unconditionally.** The callee deliberately sets `cols=[]` when there are no departure targets, then interprets that empty list as “no arrival column eligible” and returns `blocked`, even if the sheet is certified. The torus driver later fails its launch assertion. **Fix:** distinguish “zero required rib units” from “zero certified arrival roots” and package a sheet-only library through the no-rib path. Also, the supplied entrypoint does **not** implement the rootless-start commit’s title: it requires a nonempty anchor table and downstream code requires arcs. Either wire in an explicit first-root initialization stage or document that the new `physicsOnly` support is merely a helper capability, not a rootless `run_phase_torus` interface.

- **[ROBUSTNESS]** `run_phase_torus.m:330–373,704–706` — **The input table rejects only top-level typos and admits budgets that break its control flow.** `withDefaults` correctly fills partial structs, but retains unknown nested fields: `engine.thrustn` silently leaves the default `thrustN` active. There are no finite/integer checks for worker/round/step counts, no positive finite check for `.arc.span`, and incomplete validation of thresholds and flags. For example, `maxRounds=1.5` passes, executes only round 1, never satisfies `k==maxRounds`, and can publish with status `running`. **Fix:** validate scalar structs recursively against their allowed fields; require real finite scalars, integer counts, positive finite spans and appropriate threshold/flag domains. Validate anchor phases and safe filename tokens for names/tags before launching anything.

## D. Ranked top-5 by expected campaign cost

1. **Make process ownership and verdicts generation-safe.** Duplicate arc writers, stale PID cancellation and supervisor races can corrupt products or waste full multi-hour/48-hour deadlines.
2. **Preserve and consume committed roots across recovery.** Transaction gaps, cached sheets and the `fh.nCert` gate can lose useful families or certified cells despite their data being on disk.
3. **Finish publication before declaring termination.** Consume last-round discoveries, enforce audit/sweep outcomes, and make final publication recoverable.
4. **Thread the actual problem and anchor context everywhere.** Current nondefault-phase/engine campaigns can spend hours on arcs before failing against a default setup.
5. **Use root identity consistently.** Replace the rib’s 0.5-day test and time-only registry/family matching; otherwise necessary walks and new families can be silently suppressed.
