This is a static review of the supplied code. The implementations of `build_ribs`, `build_arrival_sheet`, and `build_70mN_library` are not supplied, so their save, checkpoint, and input-validation contracts cannot be assumed.

The demand-driven queue is the right direction. However, the current integration still permits duplicate ownership, interruption of productive work, false completion, and destructive “resume.”

## 1. Entry point, staging, and resumability

- **[CORRECTNESS]** `work_queue.m:98,134; run_costate_library.m:80,93` -- **File existence is not a completion contract.** A file can exist while MATLAB is saving it, after an interrupted save, after an initial checkpoint, or with only part of a column completed. All these cases are accepted as DONE. The queue cannot establish correctness merely by declining to maintain a separate completion flag. **Fix:** distinguish checkpoints from committed results. Write to an attempt-specific temporary file, validate its schema, campaign identity, and required terminal work coverage, then publish it atomically on the same filesystem. Only that validated final artifact counts as done. A legitimately incomplete numerical result must carry explicit unresolved-cell information, not silently satisfy the completion test.

- **[CORRECTNESS]** `run_costate_library.m:75,90,114,146` -- **Artifact names do not identify the computation.** The sheet filename includes `nA` but not `sA0` or source-arc identity. Rib filenames include only the column index, omitting both grid dimensions and the actual departure/arrival phases. Increasing `nD` can therefore accept an old, shorter rib as complete. Changing `nA` can reuse column `j` even though that index now denotes a different arrival phase. The subset relationship between doubled grids does not make index-based filenames reusable. **Fix:** introduce an immutable campaign manifest containing the grid coordinates, operating-point/configuration identity, arc provenance, and artifact schema. Namespace outputs by that identity; reuse certified cells only through explicit coordinate/provenance matching.

- **[CORRECTNESS]** `run_costate_library.m:114; work_queue.m:77-85` -- **A re-run destroys live ownership.** Every entry-point invocation overwrites `queue.mat` and removes every claim directory, without establishing that existing workers have stopped. Re-running to inspect progress or package can free columns that are still being computed. Existing workers then continue against a replaced queue and claim namespace. The in-place `save` also races with workers loading `queue.mat`. **Fix:** separate `create`, `open/resume`, and explicit `reset/migrate`. Normal resume must preserve claims and verify the existing manifest. Serialize initialization with a controller lock, publish the manifest atomically, and prohibit destructive reset while workers are active.

- **[CORRECTNESS]** `work_queue.m:79-81; run_costate_library.m:114` -- **Resume resets the retry budget and reintroduces the cross-run livelock the comments claim to prevent.** A solver-hanging unit spends an attempt, but the next ordinary driver invocation deletes that evidence. Three failures can become three more failures indefinitely. **Fix:** persist attempts and their outcomes for the lifetime of the campaign/input version. Resetting a retired unit must be an explicit, recorded operator action or follow a relevant input/code change—not happen during `init`.

- **[CORRECTNESS]** `run_costate_library.m:122-144; run_campaign_workers.sh:49-67` -- **Launching is followed by packaging without a completion barrier.** The launcher verifies startup and does not join the workers or establish queue completion. The driver then immediately invokes package/audit/sweep. It also ignores the launcher's exit status, so a failed launch takes the same path. Packaging can consequently read incomplete or actively changing rib files. **Fix:** check the `system` status and return an explicit launch failure if necessary. After successful startup, either return `pending` or supervise until the campaign reaches a defined terminal state. Partial diagnostic packaging is reasonable only as an explicitly incomplete, consistent snapshot with blockers—not as the ordinary completed chain.

- **[GAP]** `run_costate_library.m:126-129,134-146` -- **The early `return` makes the default operation a preparation step, not an end-to-end campaign.** Printing the command is legitimate manual-mode behavior, but nothing schedules the later packaging invocation, and the returned structure has no explicit `prepared`/`waiting` state. Worse, the instructed re-run currently performs the destructive initialization above. **Fix:** make the lifecycle explicit, for example `prepare`, `launch`, `wait`, and `finalize`, with a persistent campaign ID and returned state. Both launch modes should have consistent completion semantics, and `finalize` must open—not reinitialize—the queue.

- **[ROBUSTNESS]** `run_costate_library.m:140-144` -- **The base-workspace handoff is process-global mutable state, not an isolated call.** It overwrites any existing `chainOverrides`, does not restore it after success or failure, and allows the script to interact with unrelated base-workspace variables. The comment that base is the only workspace available is generally false: an ordinary script executes in its caller's workspace. If this particular script explicitly reads the base workspace, that reader is the coupling that needs removal. **Fix:** convert the chain to `result = build_70mN_library(co)`. As a transitional measure, save and restore the previous base variable with `onCleanup`; that still does not isolate the script's other side effects.

- **[GAP]** `run_costate_library.m:135-144` -- **The downstream handoff does not establish which library is being packaged.** It passes `outDir` and switches, but not `sheetMat`, `nD`, `nA`, `sA0`, an explicit rib list, or a campaign manifest. The unseen chain might infer these correctly, but nothing here establishes that contract, especially when the directory contains products from different resolutions. **Fix:** pass the manifest and exact input artifact set to the chain, and require identity checks before consuming them. Do not rely on default filenames or directory globs. Make `pictures` an explicit stage option rather than forcing it on.

- **[GAP]** `run_costate_library.m:73-74,143-146` -- **The public result cannot communicate the advertised blockers or actual finalization outcome.** `out.blockers` is initialized and never populated. No chain result is retrieved. `out.catalog` becomes an expected filename even if packaging was disabled or no valid catalog was produced. **Fix:** return structured stage outcomes, actual validated output paths, pending units, retired units, and audit/sweep blockers. Keep an expected output path separate from an artifact asserted to exist.

- **[CORRECTNESS]** `run_costate_library.m:85-86,101,114` -- **Unseeded arrival columns disappear from the campaign denominator; an entirely unseeded sheet crashes calibration.** `cols` contains only finite `S.TF` entries. The queue can report all of its units complete while requested arrival columns were never eligible for work. With no eligible columns, `cols(1)` throws. Sparse or unsuccessful numerical results need not abort useful downstream analysis, but they must not vanish from orchestration accounting. **Fix:** retain the complete requested grid in the manifest, mark unavailable seeds as blocked, and report their coverage separately. Handle an empty eligible set explicitly without indexing it or pretending an empty queue means a complete library.

- **[CORRECTNESS]** `run_costate_library.m:92-106` -- **Calibration bypasses ownership and retry accounting.** It calls `build_ribs` directly before initializing/opening the queue. If a previous launch is computing its first column but has not published an output, a re-run can start that same column as calibration. Calibration failures also bypass the queue's attempt policy. **Fix:** create/open the campaign first and perform calibration through the same claim, attempt, checkpoint, validation, and commit protocol as ordinary work. Alternatively, collect timing from an already claimed worker instead of running a separate untracked solve.

## 2. Timing, worker behavior, and preservation of expensive work

- **[CORRECTNESS]** `run_costate_library.m:161-164; campaign_worker.m:50,64-69` -- **The generated unit function discards `beat`. This makes legitimate multi-hour columns reclaimable after 30 minutes.** The callback appears in the anonymous-function signature but is never passed to or called by `build_ribs`. Worker and claim heartbeats are therefore updated only at unit boundaries. When a faster worker finishes, it can reclaim another worker's still-running column. The monitor will also classify productive workers as stalled. **Fix:** add a real progress callback to the walker/corrector integration and invoke it at documented, bounded intervals. A MATLAB timer alone is not a reliable substitute while MATLAB is blocked in long-running native code.

- **[CORRECTNESS]** `run_campaign_workers.sh:26-32,41-44; campaign_worker.m:58-69` -- **The watchdog is a total-process lifetime timer, not a hang detector or a between-unit budget.** It is never reset by progress or a new claim. Even if every column finishes faster than `WATCHDOG`, a healthy worker processing several columns eventually gets killed inside one. “Longer than one measured unit” does not protect a process that executes many units, and `4 × one sample` does not bound even a single unusually long unit. **Fix:** separate a drain deadline from hang detection. A drain request stops new claims and permits the current unit to finish or checkpoint. A hang policy must use bounded progress expectations and safe cancellation/recovery, not elapsed lifetime from process launch.

- **[GAP]** `run_costate_library.m:93-110` -- **The 3600-second calibration fallback is a trap, not a conservative default.** It is below the stated 90-minute lower end of actual column times and far below the long tail. The first invocation may measure a column, but that timing is not persisted; a later invocation replaces it with a guess as soon as any rib file exists—even an invalid one. The first eligible column is also not a defensible upper-tail estimate. **Fix:** persist per-attempt timing with work coverage, completion status, configuration, and resource allocation. Reuse compatible measurements and report uncertainty. Treat sampled durations as planning estimates, never as evidence that killing a slower column is safe.

- **[GAP]** `run_costate_library.m:104-107,119-121,161-164; campaign_worker.m:50-51` -- **The claim that every budget is sized from measurement is not implemented.** `unitSec` feeds the shell watchdog. Generated workers receive neither `budgetSec` nor `staleSec`; the former stays infinite and the latter stays 1800 seconds. Both calibration and production hardcode `wallSec = 900`. If that is a whole-column cap, calibration can measure a censored 15-minute attempt rather than a completed column; if it is a lower-level cap, it is still unrelated to the advertised calibration. **Fix:** document `wallSec` precisely, verify that calibration completed the intended work, and configure each policy explicitly. Lease freshness should derive from heartbeat cadence, not column duration.

- **[GAP]** `campaign_worker.m:16-20,69,78; run_costate_library.m:161-162` -- **Reclaiming a column does not recover the hours already spent on it.** This interface only supplies the unit ID, callback, and final output path. It establishes no checkpoint/resume contract for the bisecting walker. The queue can make a dead worker's column available again, but that is not evidence that nine hours of progress survive. **Fix:** require periodic, validated checkpoints containing completed cells and enough walker state to resume safely. Keep checkpoint artifacts distinct from final artifacts and associate them with the input manifest and attempt lineage. If the walker already supports this internally, expose and test that contract here.

- **[GAP]** `campaign_worker.m:61-62` -- **“No claim available now” is incorrectly treated as “queue empty.”** All unfinished units may merely be held by other workers. Idle workers exit rather than waiting for a failure or lease expiry. At the tail, a worker can die while its peers have already exited, leaving nobody to perform reclamation. **Fix:** distinguish complete, blocked/retired, temporarily unavailable, and retryable work. Keep some workers polling with bounded backoff, or have a supervisor restart dispatchers. Termination must depend on campaign state, not one unsuccessful claim call.

- **[CORRECTNESS]** `campaign_worker.m:69-75` -- **A normal function return is counted as DONE without checking the output contract.** A unit function that returns without writing a valid artifact can be counted as done repeatedly until the queue retires it. Conversely, a function that commits valid work and then throws during reporting is counted as failed. The worker and queue can disagree even under the stated “artifact, not flag” philosophy. **Fix:** make validated publication the success boundary. Prefer having `unitFcn` return an attempt result/temp artifact and letting the worker validate and commit it. Separate computation, commit, and reporting outcomes.

- **[CORRECTNESS]** `campaign_worker.m:55-65,78-85` -- **Fatal worker failures do not reliably produce a failed worker state.** Queue loading/claiming, initial heartbeats, logging, and release can throw outside the unit `try/catch`. There is no outer failure handler, and this worker never calls `campaign_heartbeat('fail', ...)`. Caught unit failures eventually lead to a `done` heartbeat even if no required work succeeded. **Fix:** add a top-level guarded lifecycle that records fatal initialization/runtime failures and exits nonzero. Use ownership-safe cleanup. Distinguish clean worker shutdown from campaign success and from unresolved unit failures; a budget stop is not proof the campaign is done.

- **[CORRECTNESS]** `campaign_worker.m:70-75,98-103; safe_report.m:33-41` -- **Reporting can still fail saved work—and can double-count one attempt.** The DONE log call is inside the work `try`. If it throws, `nDone` has already incremented, then `nFail` increments too. The catch then attempts another write to the same possibly broken log and can abort before release. Other log calls are unguarded as well. The visible `safe_report` integration does not protect this path. **Fix:** perform outcome accounting once at the commit boundary and make subsequent reporting best-effort, with a fallback channel. Do not count a logging failure as a solver failure. Also, `safe_report` should not assert “the output is on disk” unless its caller has established that fact.

- **[ROBUSTNESS]** `campaign_worker.m:68-78; work_queue.m:97-111` -- **All exceptions consume the same retry budget, with immediate retries and no shared-failure circuit breaker.** A missing dependency, unwritable output directory, or other campaign-wide infrastructure failure can rapidly retire every unit. Repeating a deterministic failure immediately with identical inputs is often just expensive duplication. **Fix:** record structured attempt diagnostics and classify infrastructure failures separately from unit-local failures. Pause the campaign on shared infrastructure faults; use bounded backoff and an explicit retry policy for recoverable unit errors. Preserve `ME.identifier` and a full diagnostic report, not just the message.

## 3. Queue atomicity, ownership, and crash consistency

- **[GAP]** `work_queue.m:19-22,101-107; tests/test_work_queue.m:42-45` -- **The atomic-claim claim is stronger than the implementation evidence.** A native exclusive `mkdir` on local APFS has one creator. MATLAB's `mkdir` reports success for an existing directory; your `DirectoryExists` message-ID rejection addresses the normal exists case, so the initial `isfolder`/`mkdir` gap alone is not a demonstrated double-claim bug. But the code relies on the wrapper preserving a distinguishable losing result under actual contention, and the test is sequential. **Fix:** use a documented exclusive-create primitive with explicit “already exists” handling, and test simultaneous contenders using separate MATLAB processes on each supported MATLAB/filesystem combination. This still will not repair the stale-reclaim protocol below.

- **[CORRECTNESS]** `work_queue.m:101-105` -- **Stale reclamation has both a check/delete race and a multiple-reclaimer race.** A worker can refresh its beat after another process checks the age but before that process removes the directory. Worse: A and C both observe B's stale claim; A removes it and creates a fresh claim; C then removes A's fresh claim based on its earlier observation. Both can end up computing the same unit. **Fix:** serialize ownership transitions and perform conditional takeover of the specific observed owner/generation. A plain “stat, then recursive delete” is not a lease protocol. Use a transactional coordinator or an equivalent rigorously specified per-unit transition mechanism.

- **[CORRECTNESS]** `work_queue.m:109,115-122,176-180; campaign_worker.m:67,78` -- **Claims have no ownership token or fencing, so old workers operate on new owners' claims.** Every attempt uses the same `N.claim` pathname. After takeover, the old worker's `beat` refreshes the replacement claim and its `release` deletes that replacement. The beat action even replaces the original worker tag with the literal `beat`. Both workers can also publish to the same final output. **Fix:** assign each acquisition a unique owner token and fencing generation. Heartbeat, release, and result publication must be conditional operations against that token under the serialized ownership protocol. Write attempt-specific outputs and reject publication by superseded owners. A UUID check followed by an unprotected delete is still a race.

- **[ROBUSTNESS]** `work_queue.m:105-110,184-191` -- **The mkdir-to-metadata window has no well-defined recovery state.** A process can die or pause after creating the directory but before writing the beat and attempt record. Missing beat data is handled with `dir(cf)`, which lists directory contents rather than reliably obtaining the claim directory's own metadata; selecting its first entry is not a sound ownership timestamp contract. **Fix:** define an initializing/reserved state and a recovery grace period, with reliable reservation metadata. Do not start work unless ownership and attempt reservation have been successfully persisted. Recovery must distinguish incomplete claim creation from an expired, fully initialized owner.

- **[CORRECTNESS]** `work_queue.m:98-110` -- **Completion and retry eligibility are checked before ownership, but never rechecked after acquiring it.** A contender can observe no output, pause, and later acquire the directory after the previous owner has completed and released it. It will redo already committed work. Similarly, a contender can pass the attempt-limit check before another attempt consumes the final retry. **Fix:** after acquiring exclusive ownership of the unit transition, re-read committed completion and the authoritative attempt count before reserving the next attempt. Release without work if the unit has become complete or ineligible.

- **[CORRECTNESS]** `work_queue.m:156-172,176-180` -- **Attempt and ownership persistence fail open.** An unreadable/corrupt attempt record can become zero; an empty record after truncation becomes zero; an `fopen` failure in `bumpAttempt` or `writeBeat` is silently ignored. The worker can therefore perform expensive work without a recorded retry expenditure or usable lease record. **Fix:** fail the claim closed on persistence errors. Validate counters as nonnegative bounded integers, and treat corruption as a repair/blocker condition, not “never attempted.” Persist the increment atomically under exclusive ownership, check all I/O results, and keep a durable attempt ledger sufficient to reconstruct state.

- **[CORRECTNESS]** `work_queue.m:129-148` -- **Queue status is not a partition of unit states.** A live third attempt has `att >= maxAtt`, so it is reported as both running and retired. Counts can exceed the number of units. Separately, stale claims are reclaimable but excluded from `nTodo`, so `nTodo == 0` does not mean complete or even that no dispatchable work exists. **Fix:** give each unit exactly one primary state, with metadata such as `lastAllowedAttempt`. Distinguish active final attempts from exhausted inactive units. Expose explicit predicates for complete, blocked, available, and awaiting-owner/recovery, rather than asking callers to infer them from `nTodo`.

- **[GAP]** `work_queue.m:92-93,129-140; campaign_worker.m:61; campaign_status.m:33-35` -- **Workers, queue status, and monitoring can apply different policies to the same state.** Queue status hardcodes 1800 seconds. `campaign_status` forwards its `staleSec` only to heartbeat reading. `claim` supports `maxAtt`, but `campaign_worker` never forwards one, while status can accept a different value. **Fix:** store authoritative lease/retry policy in the campaign manifest and apply it consistently. Monitoring overrides should change presentation or alarm thresholds—not silently redefine queue ownership differently from the workers.

- **[ROBUSTNESS]** `work_queue.m:101-105,184-191; campaign_heartbeat.m:73-85` -- **Filesystem namespace atomicity does not make mtime-based leases reliable across hosts.** Local APFS does not remove the application-level reclaim races. NFS normally provides server-side atomic directory creation, but attribute caching, visibility delays, client/server clock differences, and transient I/O errors can make a fresh owner appear stale. Clock jumps can also produce negative ages or premature expiry locally. **Fix:** state the supported storage/clock assumptions and test them. Prefer a coordinator-owned lease clock and monotonic observation deadlines. Treat uncertain filesystem observations as unknown/suspect, not permission to delete ownership. For one host, kernel-held interprocess locks plus an exact-child supervisor may be simpler; do not assume a shared SQLite file on NFS is a safe substitute.

## 4. Heartbeats and monitoring

- **[CORRECTNESS]** `campaign_heartbeat.m:53-56,73-85` -- **A fresh empty or corrupt heartbeat is classified as running.** Writers truncate the live file in place. A reader can observe it between truncation and write, or after a writer crashes there. Any unknown first token falls through to the freshness test and is considered healthy. The separate `dir` and `fileread` operations also race with removal/replacement. **Fix:** atomically replace complete heartbeat records, validate the record format and identity, and classify malformed/unreadable records as unknown or failed telemetry. Unknown text must not imply `running`.

- **[GAP]** `campaign_heartbeat.m:20-26,68-85; campaign_worker.m:55,84` -- **The five labels overstate what the evidence proves.** Missing telemetry does not prove a process never started: MATLAB may be loading, waiting for a license, or failing before its first heartbeat. A fresh beat proves recent reporting, not present process health or computational progress. A `done` marker proves worker shutdown only—not completed campaign work. A dead process can remain “running” until expiry, which is an unavoidable detection delay, not something the file format eliminates. **Fix:** distinguish startup/readiness, process liveness, useful progress, and terminal outcome in the record and monitor. Label absence as “no check-in observed,” and make campaign completion a separate validated-artifact calculation.

- **[CORRECTNESS]** `campaign_heartbeat.m:53,80-85; run_campaign_workers.sh:38-40` -- **Terminal records have no campaign or worker-instance identity.** An old `done` marker is accepted indefinitely for the same tag. Tags are reused on every launch, so records from different process instances can overwrite one another. One worker's normal exit can mask another worker's ongoing or failed work under that tag. **Fix:** bind every record to a persistent campaign ID and a unique launch/worker-instance ID, with host, PID/start identity, queue identity, sequence, and current ownership token. Accept terminal records only for the expected instance.

- **[GAP]** `campaign_status.m:34-55` -- **The monitor does not reconcile worker records with claim ownership.** It counts recent worker heartbeats and queue states independently. It does not establish that an active claim belongs to an expected worker, that the worker reports the same unit, or that apparent live workers are attached to this queue. It also calls stale claims “dead” without evidence of death. **Fix:** join the worker registry to owner-token-bearing claims. Alarm on orphan ownership, contradictory unit assignments, superseded writers, and incomplete work without an accountable owner. A stale claim should initially be described as a lost/suspect lease, not a dead process.

- **[GAP]** `campaign_status.m:32-68; run_campaign_workers.sh:49-67; run_costate_library.m:123-145` -- **There is no unattended monitoring/recovery loop in the supplied chain.** `campaign_status` is an on-demand function. The launcher checks startup once, then leaves only destructive lifetime timers. Nothing here continuously alerts, replaces failed workers, revisits abandoned claims, or triggers finalization after completion. **Fix:** add a durable supervisor—or use an existing batch scheduler—that tracks expected worker instances, consumes exit statuses, polls campaign state, performs bounded restarts, issues alerts, and schedules finalization. The supervisor must respect persistent retirement, not restart poison work forever.

## 5. Generated jobs and launcher correctness

- **[CORRECTNESS]** `run_costate_library.m:156-166` -- **Generated workers bootstrap from a hardcoded checkout and derive code paths from the output directory.** This can fail on another machine or silently run code from a different checkout. Even under the default layout, the triple `fileparts(sheetMat)` expression produces `.../DRO_tulip/costate_common`, not the sibling `.../costate_common` added by the entry point. `addpath(fileparts(sheetMat))` adds the results directory, not the solver source directory. A broad `startup` might mask this defect. **Fix:** derive code roots from the driver's actual source location and record the chosen source revision. Pass those absolute roots explicitly; never infer source layout from `outDir`.

- **[CORRECTNESS]** `run_costate_library.m:67,75,90,117,160-166; run_campaign_workers.sh:41` -- **Relative `outDir` paths change meaning inside `run(jobScript)`.** MATLAB `run` executes a script with its directory as the working directory. A job generated using a relative path such as `results/rib_unit_job.m` can then resolve its embedded `results/...` paths beneath `results` again. Queue paths and the saved output-function closure are similarly sensitive to working directory. **Fix:** canonicalize every source, manifest, queue, output, heartbeat, and log path to an absolute path before saving or launching anything. Worker correctness should not depend on inherited or script-modified `pwd`.

- **[CORRECTNESS]** `run_costate_library.m:119-125,154-166; run_campaign_workers.sh:41` -- **There are two unescaped language boundaries.** The driver's `out.cmd` inserts filenames into a shell command without quoting. The generated MATLAB source and `run('$JOB')` insert paths into MATLAB character literals without escaping apostrophes. Spaces can break the outer command; shell metacharacters or a quote in a valid filename can execute something unintended or produce invalid MATLAB. **Fix:** use a stable worker function and a data manifest rather than generated MATLAB source. Where a command string remains necessary, apply separate, tested shell-argument quoting and MATLAB-literal escaping. Do not conflate those two encodings.

- **[CORRECTNESS]** `run_costate_library.m:117-118,167` -- **The executable job file is mutable shared run state.** Every re-run truncates and rewrites `rib_unit_job.m`, without an I/O check or atomic publication. A worker starting concurrently can read a partial script or a script generated for a different configuration. **Fix:** use an immutable, versioned job/manifest per campaign or launch, written and validated before workers start. Better, eliminate the generated script in favor of a checked-in worker entry function. Check `fopen`, writes, and close/publication errors.

- **[GAP]** `run_campaign_workers.sh:49-67; campaign_worker.m:55-61` -- **Startup verification proves only that some file with that name appeared.** The initial heartbeat is written before the queue is loaded or a unit is claimed. A worker can write it, immediately fail, and still pass verification. `fail` and `done` files also pass. A wrong job connected to the wrong or empty queue can pass if it writes the expected tag. **Fix:** require a structured READY acknowledgment containing the launch nonce, expected queue/manifest hash, worker-instance identity, and resource/configuration summary, emitted after preflight succeeds. Check early process exit as well, and continue supervising after READY. Do not print “all workers running” from file existence.

- **[GAP]** `run_campaign_workers.sh:20-27,36-47,63-67` -- **Invalid worker counts can launch nothing and report success.** `N=0` or a negative count can produce no loop iterations, an empty `FAILED` array, and `LAUNCH OK`. A malformed `seq` invocation can also leave an empty list without a reliable failure path. `set -u` is not input validation or error handling. The fallback MATLAB executable, job readability, and output-directory writability are not verified either. **Fix:** validate a positive integer worker count and positive bounded duration; validate the exact executable, readable absolute job/manifest path, and writable output paths before launching. Verify the number of children actually created. Explicitly handle failures; merely adding `set -e` does not handle failed background jobs.

- **[ROBUSTNESS]** `run_campaign_workers.sh:22-25; run_costate_library.m:163-166` -- **Launcher and worker can disagree about the heartbeat directory.** With three arguments, the launcher defaults to `dirname(JOB)/campaign/hb`; the generated job writes to its embedded `outDir/hb`, normally `dirname(JOB)/hb`. Passing a different fourth argument likewise changes where the launcher looks without changing where the job writes. **Fix:** make one manifest authoritative for the queue, heartbeat, and log directories. Both launcher and worker should consume it rather than independently inventing defaults.

- **[CORRECTNESS]** `run_campaign_workers.sh:38-45; run_costate_library.m:159` -- **Relaunching reuses identities and clobbers evidence from live workers.** Each launch reuses `w1`, `w2`, etc., deletes their heartbeat files, and truncates their stdout logs. Existing workers may still hold the old log descriptors and continue updating the shared names. The generated script's fallback to `w0` also silently permits identity collisions when invoked outside the launcher. **Fix:** require a valid supplied worker identity; do not silently default it. Use unique instance-scoped directories and preserve logs. A new launch must either intentionally add unique workers to an existing campaign or establish that the previous launch is stopped.

- **[ROBUSTNESS]** `run_campaign_workers.sh:52-65` -- **The advertised 120-second verification timeout is sequential and does not establish a startup outcome.** Later workers can receive several earlier workers' worth of additional waiting time. Conversely, a legitimate slow license/startup path can check in after it has been declared “DID NOT START.” The launcher exits failure but leaves already-started and late-starting workers unmanaged, encouraging a duplicate relaunch. **Fix:** track a per-child launch timestamp and configurable startup deadline concurrently. Detect early exits promptly. On timeout, report an uncertain/not-ready instance and either stop it deliberately or keep supervising it; do not abandon it as though no process exists.

- **[CORRECTNESS]** `run_campaign_workers.sh:42-45` -- **Sleeping watchdogs can outlive their workers and later kill an unrelated reused PID.** They are never canceled when the child exits. `kill -0` establishes only that something currently has that PID, not that it is the original MATLAB instance. There is also no reliable process-tree shutdown for MATLAB helpers/pools. **Fix:** supervise the actual child lifecycle, cancel and reap associated timers on exit, and bind control to a stable process identity or managed process group/service. Preserve and inspect exit statuses. Define signal handling and child cleanup explicitly.

- **[ROBUSTNESS]** `run_campaign_workers.sh:41-47` -- **Backgrounding is not a specified detachment/supervision contract.** The watchdog subshell retains inherited standard descriptors, and there are no traps or explicit ownership rules for launcher exit, interruption, or parent-session loss. In pipe-capturing callers, inherited descriptors can also keep output collection open after the shell's nominal startup work has finished. **Fix:** run workers and timers under an explicit supervisor/service with controlled stdin/stdout/stderr, shutdown policy, and process ownership. Do not rely on `&` to make a robust detached campaign—or on accidental descriptor lifetime as a completion barrier.

- **[ROBUSTNESS]** `run_costate_library.m:66-70,158; run_campaign_workers.sh:21-24,41` -- **Campaign and resource configuration is largely unchecked.** Invalid dimensions, non-scalar switches, nonpositive timing values, or excessive worker counts reach expensive stages before failing. The launcher silently changes MATLAB versions when one path is unavailable. A pool cap alone does not establish total MATLAB computational-thread, memory, or license usage; calibration also does not visibly use the same resource setup as workers. **Fix:** validate the complete manifest before calibration, require an explicit supported MATLAB executable/version, and preflight licenses, memory, disk space, and concurrency. Record and enforce per-worker resource settings, then calibrate under representative contention.

## 6. Tests and regression protection

- **[GAP]** `tests/test_work_queue.m:42-60` -- **The “atomic claiming” test never creates a race.** Sequential claims only prove that the second call notices the first call's directory. The stale test has one reclaimer and no live old owner. Neither exercises the critical failure modes above. **Fix:** add separate-process barrier tests for simultaneous fresh claims, simultaneous reclaimers, and a delayed old owner that subsequently beats, releases, and tries to publish. Assert both ownership behavior and that only the current fenced owner can commit. Run these on the actual APFS/NFS deployment, not just one MATLAB session.

- **[GAP]** `tests/test_work_queue.m:40-88` -- **The test suite does not test the latest livelock fix or the assembled campaign.** There is no permanent-failure/max-attempt test, attempt persistence across resume, worker crash injection, launcher verification test, generated-job test, or end-to-end completion test. The artifact test deliberately treats an arbitrary one-byte file as complete, embedding the unsafe production assumption. **Fix:** add fault-injection tests at mkdir, metadata/attempt persistence, work execution, checkpoint write, final publication, and release. Include resume with live workers, a final surviving worker dying, zero eligible columns, wrong-grid artifacts, exhausted retries, missing dependencies, disk-write failures, and startup acknowledgment followed by immediate exit. Use short configurable timeouts so these tests run routinely.

- **[ROBUSTNESS]** `tests/test_work_queue.m:76-88,101-104` -- **Test failure need not fail a batch job or CI run.** `chk` accumulates `ok=false` and the function prints FAIL, but it does not throw. A batch command that merely calls this test can exit successfully. The report-catching test also depends on the behavior of a particular conversion rather than deliberately exercising an exception. **Fix:** use `matlab.unittest` with an asserted successful result, or invoke `assert(test_work_queue())`. Test `safe_report` with an explicit thrown error, and retain the historical conversion as a separate supported-version regression test.

- **[ROBUSTNESS]** `fmt_num.m:24,34-39` -- **The claimed fixed width is not guaranteed.** `sprintf('%*.*f', ...)` specifies a minimum width; large magnitudes or unsuitable precision can exceed it. The existing test covers only a value that fits. **Fix:** validate width/precision and define a bounded overflow representation or a scientific-notation fallback. This is minor compared with the ownership defects, but the helper's contract and tests should be accurate.

## VERDICT

**No: this chain is not fit for an unattended multi-day campaign.**

With the generated worker as written, legitimate columns stop heartbeating and become stale after 30 minutes. Reclamation can create competing owners, re-running destroys live claims and retry history, and the process-lifetime watchdog still kills productive work. Meanwhile, incomplete files can count as done and packaging can start before workers finish.

The minimum go/no-go requirements are: **non-destructive resume, durable campaign identity, ownership-safe claims and fenced publication, actual progress/checkpoint integration, supervised worker lifecycles, validated completion, and multiprocess fault-injection tests of the assembled chain.** Increasing timeout constants alone will not make this safe.
