# Design: optimality status and alternative transfers in the costate library

**Date:** 2026-10-04
**Status:** approved in design review with Mike (sections 1-5); spec awaiting review
**Scope of the first build:** the 70 mN DRO -> tulip phase library of record
(`orbit_transfer/DRO_tulip/indirect/results/library_70mN_24x48_merged/`, 1,152
entries) and the builders that produce it. The older catalogs
(DRO/HALO/DPO/HALO_HALO, 18,360 entries; min-fuel, 18 entries) are a later,
separate step.

## 1. Purpose

The library becomes a record of **orbit transfers and their thrust programs**,
not only of optimal ones. An orbit transfer does not have to be optimal to be
useful. Every entry carries an annotation of what has been established about
its optimality:

| code | name | meaning |
|---|---|---|
| 4 | sufficient | first- and second-order sufficient conditions hold (= "certified" today) |
| 3 | necessary only | first-order necessary conditions hold; sufficiency not established |
| 2 | conjugate point found | an extremal with a conjugate point on the arc, under the regularity hypotheses: **not locally optimal** |
| 1 | neither | flies to the target, but the necessary conditions are not established |
| 0 | (empty cell) | no transfer recorded |

**Intended user: a mission designer**, who must be able to find a transfer by
its phases, fly it, and read its status and the reason for it. A slower or
non-optimal transfer can be the right choice for a mission.

**Principle: a status records what was ESTABLISHED, not what might be true.**
A transfer that is probably an extremal but whose checks did not all run gets
the lower tier and says why.

### Success criteria

1. The library of record, after a backfill (section 6), carries a status and
   junction states for every primary and an `alternatives` table holding the
   harvested non-primary transfers.
2. The primaries are bit-identical to today's record (content key unchanged).
3. The extended audit is clean, including the status reproduction of every
   alternative.
4. `transfers_at` + `fly_transfer` give a designer every transfer at a phase
   pair, ranked, with its thrust program.
5. Existing readers (pickers, audit's primary pass, interpolator,
   `merge_phase_catalogs`, `compare_phase_catalogs`, deliverable helpers) work
   unchanged on the new file.

## 2. Decisions (from the design review)

- **Per cell: all distinct transfers found, ranked by t_f.** The cell's
  PRIMARY stays the fastest status-4 transfer, in the existing grid, so
  existing readers are unchanged (approach A: alternatives table inside the
  catalog; B "flat entry table" and C "companion file" rejected).
- **Storage per entry: z8 + multiple-shooting junction states.** The thrust
  program is regenerated by a segment-wise flight from the junctions; no
  sampled histories stored. (Re-flying a bare z8 over 17-26 days amplifies
  costate error 2.5e5-6.7e6 km per unit relative error, FINDINGS 97; the
  binding rule of 2026-08-25 is to ship junction states.)
- **Admission floor: a converged indirect root that flies to the target**
  within the existing gates (100 km, 10 m/s). Direct-only solutions are not
  admitted (no reliable costates).
- **Coverage: going forward + a cheap harvest** of what is on disk; no full
  rebuild.
- **The certifier runs the hypothesis gates after a conjugate failure**, for
  the record, so a status-2 label is backed by the hypotheses it needs.
- **Ribs may walk past a conjugate point: opt-in, off by default.**

## 3. Data model

### 3.1 The existing sheet (primaries) gains three fields

| field | type | meaning |
|---|---|---|
| `status` | `int8 [nD x nA]` | code of the cell's primary (4 for every filled cell today; 0 empty) |
| `status_reason` | `cell {1 x nEntries}` | "full stack passed" for status 4; otherwise the first failed or unrun check, in the certifier's words |
| `junctions` | `cell {1 x nEntries}`, each `[14 x K]` | the primary's ms junction states (state + costate at K junctions; K = 24 today) |

Every other sheet field keeps its meaning. `has_solution`, `tf_nd`,
`entry_index`, `z8` still describe the primaries only.

### 3.2 A new top-level table `alternatives` (struct array, one row per transfer)

| field | meaning |
|---|---|
| `sD`, `sA` | exact phases |
| `iD`, `iA` | the cell on the grid, or 0 when off the grid |
| `z8 [8 x 1]`, `junctions [14 x K]`, `tf_nd` | the transfer |
| `status`, `status_reason` | as in section 1 |
| `conj`, `gates`, `flyKm`, `flyVms` | the numbers behind the status (conjugate verdict incl. zero / sign change / unresolved; min\|lam_v\|, Q_mt, dim S, H6 margin, lift margin; flown miss) |
| `inferred` | true when the status was inferred from a legacy record (section 4.3) |
| `source` | provenance, e.g. `sheet nA96 cand, arc 70mN_anchor_dn`, `rib s_A 0.2837 stop`, `displaced primary (merge)` |

Rules: **one root, one record** -- no cell (and no off-grid phase pair) holds
two rows of the same root, identified by costates (`sameRoot`: the seven
costates within 1e-6 relative, t_f compared); a transfer that is a cell's
primary is never also an alternative. Ranking within a cell is by t_f.

### 3.3 A legend `status_key` in the catalog

The five codes, their meaning, and the order of the checks that define them
(section 4.2), so the file explains itself to a recipient, as `notes_key` does.

## 4. The classifier

### 4.1 One pure function

`optimality_status(C)` -> `[code, reason, inferred]`, in `costate_common`
(generic by construction: it reads certify_root's output fields, not CR3BP
specifics). Both the certifier (stamping) and the harvester (inference) call
it, so they cannot disagree.

### 4.2 The mapping, in the certifier's order

| outcome | status |
|---|---|
| polish did not converge; flight inadmissible; flown miss > 100 km or > 10 m/s | not recorded (below the floor) |
| rho < 0 (the costate normalisation has the wrong sign); a pointwise Pontryagin check fails (Hamiltonian, transversality, adjoint, minimum-principle gap, throttle) | 1 neither |
| pointwise checks pass; the `tfMin` witness disagrees, times out or throws | 1 neither ("necessary not confirmed: witness ...") |
| necessary established; conjugate test UNRESOLVED or not run | 3 necessary only |
| necessary established; conjugate test finds a definite zero or sign change; hypothesis gates hold | 2 conjugate point found |
| as above, but the gates do not hold (or could not run) | 3 necessary only ("conjugate point found, but its hypotheses were not established") |
| necessary established; conjugate test passes; a gate fails (min\|lam_v\|, Q_mt, dim S != 1, H6, lift margin, X2 cross-checks) | 3 necessary only |
| everything passes | 4 sufficient |

A check that could not run (cap exceeded, worker error) never creates a
status of its own: the entry gets the highest tier actually established, with
"<check> not checked" as the reason.

### 4.3 Inference for legacy records

Harvested candidates from before this change carry `reason` text and fields
but no stamp. `optimality_status` infers from the populated fields first
(e.g. finite `Hmax`, `fullGap` within tolerance -> pointwise passed; `conj`
value; `conjDense` content), from the reason text second, and when it cannot
place a record it takes the LOWER tier and sets `inferred = true` with the
reason "inferred: <why>".

## 5. Builders (going forward)

| unit | change |
|---|---|
| `certify_root` | stamps `C.status`, `C.status_reason` at every return via `optimality_status`; on a conjugate failure it continues to the hypothesis gates (for the record only; the result is still not ok), then returns |
| `build_arrival_sheet` / `sheet_from_arcs` | none (already keeps every candidate in `S.cand`); a harvest source |
| `rib_from_crossing` | keeps `R.refused`: every candidate above the floor, including the point it stopped at. Walking logic unchanged. New option `.walkPastConjugate` [false]: when true, a status-2 point does not stop the walk (the rib follows the extremal branch past the conjugate point; its points are recorded as status 2) |
| `fill_holes_direct` | keeps the full candidate struct of every cell attempt above the floor |
| packager (`sheet_to_catalog_file` -> `build_costate_catalog_family`) | writes `status`, `status_reason`, `junctions` for primaries; assembles `alternatives` from sheet candidates, rib refusals, filler refusals and slower certified roots that lost a cell's primary slot; dedups by `sameRoot`; writes `status_key` |
| `merge_phase_catalogs` | a displaced primary becomes an alternative (status 4, source "displaced primary (merge)"); alternatives of both catalogs are unioned and deduplicated; junctions travel with an entry (already true: per-entry fields) |

Size: a few thousand alternatives at ~2.7 KB each, ~10 MB per library. The
grid existing readers load is unchanged.

## 6. Backfill of the library of record (one batch job)

Writes `results/library_70mN_24x48_v2/`; the record is not touched until the
audit is clean and Mike adopts it (the merge's pattern, FINDINGS 94-95).

1. **Junctions for the 1,152 primaries.** Match each primary by `sameRoot` to
   a source record that holds `Y` (the builds' sheets, rib files, rib
   checkpoints, filler files, the 24 x 24 record's build). Unmatched:
   regenerate by re-polishing from the entry's own z8 (1-2 iterations from a
   true root, FINDINGS 88), fenced; it must stay within `tolMove` = 1e-6 or
   the entry is flagged, not written.
2. **Harvest alternatives** from disk: the arrival-sheet candidates of the
   24 x 48 build (nA48), the 24 x 24 build (nA24) and the 96-phase sheet
   (656 candidates, 406 refused); the 96-phase departure rib's 79 certified
   points (on-grid ones dedup against primaries; off-grid ones enter as
   status-4 alternatives); the 96-phase sheet's off-grid winners (every second
   arrival column); and the rib's stop point at s_D 0.1716, re-solved in one
   step from 0.1771 under the new certifier.
3. **Gates for harvested conjugate refusals** (~370+ that never ran them),
   fenced, so each gets status 2 or 3 by the rule of section 4.2.
4. **Package, audit, compare.** Acceptance: primaries' content key identical
   to the record's; `compare_phase_catalogs` against the record shows no
   change on any cell; extended audit clean.

Not recoverable without a rebuild: candidates the old ribs and filler never
saved beyond what their checkpoints hold.

## 7. The audit (extended, fail closed)

- **Primaries:** as today, plus status == 4 and junction consistency (flown
  segment by segment from the junctions: endpoint states reproduced, junction
  defects small).
- **Alternatives:** endpoints rebuilt from the entry's own phases; flown from
  its junctions; must clear the floor; **status reproduction** -- the defining
  check is recomputed and must agree with the stored status:

  | status | recomputed |
  |---|---|
  | 4 | the full certify_root stack |
  | 2 | the conjugate test (definite zero or sign change) + the gates |
  | 3 | the specific check that failed or was unresolved |
  | 1 | the specific pointwise or witness check that failed |

  A status that cannot be reproduced is a BAD row. A "not optimal" label meets
  the same bar as a "certified" one.
- The audit stays bound to its catalog by TWO keys: `catalog_content_key`
  (primaries, unchanged -- so the backfill acceptance of 6.4 can compare it
  with the record's) and a new `alternatives_content_key` (MD5 of each
  alternative's phases, status and z8). The audit stores both; a reader
  relying on the audit checks both.

Estimated cost: hours (full stack only on status-4 alternatives; seconds to a
minute for statuses 1-3).

## 8. The lookup (for a mission designer)

- `transfers_at(cat, sD, sA, opts)`: every transfer at those phases (primary +
  alternatives within `opts.tol`, default 1e-6 in phase), ranked by t_f; per
  row: status code and name, reason, t_f (days), Delta-V, propellant, z8,
  junctions, source.
- `fly_transfer(cat, entry, opts)`: segment-wise flight from the junctions;
  returns the trajectory and the **thrust program** (thrust direction and mass
  vs time) at `opts.nSample` resolution, and the flown miss. Built on
  `validate_flight`; displayable with `print_transfer_summary` and
  `plot_transfer_3d`.

## 9. Testing (test-first; every check gets a deliberate-failure experiment)

- `optimality_status`: one synthetic certify_root output per row of 4.2, plus
  legacy-inference cases (including an unplaceable record -> lower tier,
  `inferred`).
- `certify_root`: the stamp at each return point; gates run after a conjugate
  failure; certified results unchanged (existing suites pass).
- `rib_from_crossing`: `R.refused` holds the stop point; `walkPastConjugate`
  off = today's behaviour, on = continues and records status 2.
- packager / `merge_phase_catalogs`: dedup; displaced primary kept as an
  alternative; junctions present for every entry.
- audit: an injected wrong status, and corrupted junctions, each give a BAD
  row; a correct file passes.
- `fly_transfer`: against an independent oracle -- endpoint states rebuilt from
  the orbits at the entry's phases (`phase_state`), not the catalog's numbers.
- `transfers_at`: ranking, tolerance, off-grid lookup.
- Backfill acceptance (section 6.4).
