# DRO to ELFO Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Solve, compare and catalog minimum-time DRO to ELFO transfers with the DRO to tulip machinery, promoting pair-agnostic pieces to the shared library.

**Architecture:** The ELFO becomes an algebraic arrival family in `costate_common/get_family_orbit`, so the unchanged ladder engine solves it. A shared `pair_transfer` solves and gates one transfer for any pair; a thin campaign folder `orbit_transfer/DRO_ELFO/` holds the user script, the matched comparison, and fleet and chain scripts copied from `GTO_DRO/catalog/`.

**Tech Stack:** MATLAB R2026a, pumpkyn / pumpkynPie, CasADi 3.7.0 + IPOPT (through `casadi_mintime_dro`), proj7 (`im_elfo_optimum`, `im_elfo_states`, read only).

**Spec:** `docs/superpowers/specs/2026-11-19-dro-elfo-design.md`

## Global Constraints

- Work on `main`. Subagents never commit; the controller commits one reviewed unit at a time and pushes.
- git is `/Library/Developer/CommandLineTools/usr/bin/git`. Never stage `missiles/`, `papers/`, `.DS_Store`, `min_fuel_papers`.
- Nothing under proj7, pumpkyn, pumpkynPie, SDA, any `deliverables/` folder or any shipped catalog is modified.
- No default behaviour of `thrust_ladder_library`, `get_family_orbit` (existing families), `catalog_schema` or any shipped picker changes. `costate_common/golden_cells` stays 20/20.
- Function style: house header (purpose, inputs and outputs with sizes), no `i`/`j` indices, no `norm`, no `%#ok`, ASCII, `datetime` not `datestr`. The user script follows `SDA/run/run_ekf_tulipVelfo_cr3bp_resacc.m`.
- Subagents run MATLAB through the MCP shared session only (no `matlab -batch`, no `restoredefaultpath`, no `clear all`). Calls expected to exceed 120 s are the controller's, as its own `nohup matlab -batch` with file logs and a done-marker.
- Constants: `muStar = 0.012150585609624`, `lStar = 389703.264829278`, `tStar = 382981.289129055`, total mass `5.9736e24 + 7.35e22`, `G = 6.67384e-20`. Catalog regime: 150 kg, Isp 1710 s.
- ELFO default `oe = [12000 0.69 56.5 90]` (km, -, deg, deg), read from `im_elfo_optimum` where the IM constellation is meant.
- Recipe (stage 0): `thrLock = true`, `tf0 = 0.3`, `maxCpuSec = 600`, `maxIter = 6000`, `msHardCapSec = 300`, `floorKm = 500` (Moon), `keepDirect = true` on fleets.
- Every gate has a deliberate-failure test. Every solved transfer is written in library-entry format.
- `results/` folders are git-ignored.

## Review Focus

1. An ELFO phase at the seam (0 and 1) or a `raanDeg` outside [0, 360): the locus must return the same state for 0 and 1 and wrap the angle.
2. A transfer that the engine fails to solve: `pair_transfer` returns `ok = false` with a named reason and the user script prints it and stops before plotting, without an error stack.
3. An arrival deep in the Moon's well: clearance must use the located minimum (range-rate root), not the sample minimum; a perilune pass between samples must be caught.
4. A thrust below the last standard rung (for example 0.07 N): the rung list is built without duplicates or an empty ladder.
5. A sheet written for one `raanDeg` picked with another: `dro_elfo_pick` refuses by name instead of returning the nearest sheet.
